CASE VERDICT ANALYSIS AGENT - EXACT RUN INSTRUCTIONS
=====================================================

IMPORTANT
---------
Yes, you run "python agent.py", but only after changing into the
case_verdict_analysis_agent folder.

The new report is written to output_agent.
The existing output_codex folder is preserved and is never used as input.

Default mode is standalone "rules" mode. It uses Python only:

  - no Codex
  - no OpenAI
  - no Bedrock call
  - no local AI model
  - no Node.js or @oai/artifact-tool

Optional "bedrock" mode is still available if an ICICI environment has approved
AWS Bedrock access and wants Qwen/Titan model-generated wording.


1. OPEN POWERSHELL AND CHANGE TO THE AGENT FOLDER
--------------------------------------------------

cd "C:\Users\User\Desktop\icici-lombard-claims-extraction-uat\case_verdict_analysis_agent"

Confirm the expected folders exist:

Get-ChildItem .

You should see at least:

  agent.py
  model_corpus.py
  cloud_embeddings.py
  standalone_settings.py
  standalone_bedrock.py
  requirements.txt
  jsons
  input_pdfs
  output_agent
  output_codex


2. CREATE/ACTIVATE THE STANDALONE PYTHON ENVIRONMENT
-----------------------------------------------------

Do not use the parent project's environment as a requirement. This folder has its
own minimal requirements file.

From the case_verdict_analysis_agent folder:

python -m venv .venv
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r .\requirements.txt

Confirm the required standalone packages load:

python -c "import boto3, fitz, openpyxl; print('Standalone Python dependencies OK')"

Do not install sentence-transformers, Transformers, Ollama, FAISS, sklearn,
Torch, or any other local language/embedding model for this agent.


3. CONFIRM THE INPUTS
---------------------

All output-case artifacts must be under:

  .\jsons\<AL-number>\...

The agent recursively reads every nested file, including every _work folder,
every JSON leaf, every raw TXT line, OCR/classification/page artifacts, merged
bills, consolidated JSON, contracts and adjudication JSON.

Ground-truth PDFs must be under:

  .\input_pdfs\

PDF handling rule:

  - Every PDF under .\input_pdfs\ is accepted.
  - If a PDF filename contains an AL number and that AL exists under .\jsons\,
    the PDF is attached to that output case.
  - If the PDF is a neutral staged filename such as ground_truth_001.pdf, the
    agent maps it only when there is exactly one non-AL-named output case, such
    as the Chander Kochhar reference case.
  - PDFs that do not map to a discovered output case are still scanned as
    standalone PDF context and listed in:

      output_agent\case_verdict_analysis_agent_audit.json

  - To force old fail-fast behavior, run with:

      python agent.py --strict-pdf-mapping

An unmatched PDF does not produce an Excel row by itself because the row requires
case_verdict from an output case's consolidated_final.json. It is still accepted
as context and included in the audit.

Do not place the old Codex report in jsons. The folder .\output_codex is not read.

Optional input count check for the current supplied dataset:

(Get-ChildItem .\jsons -Recurse -File | Measure-Object).Count

The current supplied dataset should return 1375 files.


4. OPTIONAL: CHECK THE STANDALONE COPIED BEDROCK SETTINGS
----------------------------------------------------------

Run:

python agent.py --check-model-config

This step is only needed if you plan to run:

  python agent.py --analysis-mode bedrock

Expected model configuration:

  language_model_id : qwen.qwen3-vl-235b-a22b
  embedding_model_id: amazon.titan-embed-text-v2:0
  region            : ap-south-1
  local_model       : false

These values come from:

  .\standalone_settings.py

They were copied from the parent project's config defaults, but agent.py does
not import the parent project's config.py, .env files, pydantic settings, or
pipeline.clients module. The agent does not accept model-ID overrides.


5. OPTIONAL: CHECK AWS/BEDROCK ACCESS BEFORE BEDROCK MODE
----------------------------------------------------------

Run:

python agent.py --check-model-access

This makes one safe Titan embedding call and one safe Qwen JSON call.

Only use bedrock mode when this command exits successfully and prints:

  embedding_dimension
  language_model_response with status "ok"

No API key or secret-key argument is required or supported. Credentials must come
from the normal boto3 AWS chain: an IAM role, an approved AWS profile, SSO, or
the machine/runtime environment. These are AWS credentials only; they are not
read from the parent project's config.py or environment files.

If your organisation uses an approved named AWS profile, select it before running:

$env:AWS_PROFILE = "<APPROVED_PROJECT_PROFILE>"

If that profile uses AWS SSO, log in using the organisation-approved command first:

aws sso login --profile <APPROVED_PROJECT_PROFILE>

Do not paste access keys or secret keys into agent.py, config files, commands,
commits, tickets, logs, or chat.

At the time these instructions were created, this workstation's only "default"
shared-credentials profile returned an invalid security token. Bedrock mode will
correctly stop until that AWS profile/role is valid. Default rules mode does not
need Bedrock access.


6. RUN THE FULL AGENT WITH NO AI/CODEX/BEDROCK DEPENDENCY
----------------------------------------------------------

Run:

python agent.py

That one command performs the full workflow:

  1. Discovers every case in jsons.
  2. Reads every nested artifact.
  3. Flattens every nested JSON leaf path.
  4. Includes every raw/page line after identity redaction.
  5. Scans all accepted PDFs, including PDFs with no matching output case.
  6. Applies standalone deterministic cause-categorization rules.
  7. Generates exactly the seven requested Excel columns.
  8. Creates the Excel workbook using Python/openpyxl.

This default run does not incur Bedrock usage and does not need any external AI
tool. Do not close the shell while it is running.

Optional Bedrock/Qwen/Titan mode:

python agent.py --analysis-mode bedrock

Only use this optional mode after "python agent.py --check-model-access" succeeds.


7. EXPECTED OUTPUT FILES
------------------------

After a successful run, look in:

  .\output_agent\

9. TROUBLESHOOTING
-------------------

A. Error in optional Bedrock mode: invalid security token / Bedrock call failed

  - Do not add keys to the source code.
  - Activate the approved AWS IAM role/profile/SSO session.
  - Run "python agent.py --check-model-access" again.
  - Or run default rules mode with plain "python agent.py", which does not need Bedrock.

B. Optional Bedrock throttling or connection errors

Run with one model worker:

python agent.py --model-workers 1

C. Optional Bedrock model input/context-size error

Use smaller chunks (this increases the number of model calls but retains every
field and line):

python agent.py --chunk-chars 30000 --model-workers 2

D. No consolidated cases found

Confirm each case folder under jsons contains a case-level consolidated_final.json
outside _work.

E. Exit codes

  0 = successful run
  1 = runtime/workbook/dependency error
  2 = optional Bedrock model access, corpus validation, or strict output validation failure

On exit code 2 the agent does not substitute Codex or a local model and does not
produce a fake replacement workbook.
